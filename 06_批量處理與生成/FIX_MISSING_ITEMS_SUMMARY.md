# 修正損害項目遺漏問題

## 問題描述

用戶發現在生成起訴狀時,律師輸入中的某些損害項目沒有被提取到:

### 律師輸入包含的項目:
1. 醫療費用：130,698元 ✅
2. 預估未來醫療費用：150,000元 ✅
3. 看護費用：368,000元 ✅
4. 就醫交通費用：25,885元 ✅
5. 醫療用品費用：45,749元 ✅
6. 營養品費用：18,000元 ✅
7. **不能工作損失**：156,000元 ✅
8. **車輛維修費用**：13,750元 ❌ **遺漏**
9. **勞動能力減損**：200,000元 ❌ **遺漏**
10. **精神慰撫金**：600,000元 ❌ **遺漏**

### 生成結果:
- 項目1-7都正確生成
- 項目8顯示「車輛維修費用：未提及」
- 項目9被合併到項目7「減少勞動能力損失」中
- 項目10顯示「慰撫金：未提及」

## 根本原因分析

### 原因1: LLM混淆了相似概念
- **「不能工作損失」**(156,000元) ≠ **「勞動能力減損」**(200,000元)
  - 不能工作損失：短期（6個月）無法工作的收入損失
  - 勞動能力減損：永久性的勞動能力減損
  - LLM將兩者視為同一項目

### 原因2: 措辭差異導致LLM識別失敗
律師輸入的原文:
```
系爭車輛因本件事故受有損害，原告為此支付維修費用13,750元，有估價單可作為證據。

原告因系爭事故所受之傷害未能治癒，並且造成原告勞動能力減損，因此請求被告賠償勞動能力減損之損害20萬元。

最後，原告為小學畢業，擔任清潔員工作，每月收入2萬6,000元，名下無不動產，並於年屆68歲始遭系爭車禍事件，並因而受有多處骨折，接受骨釘內固定手術，手術後尚需使用氣護踝支架、石膏鞋、輪椅及柺杖，並由專人全日照顧184日，受傷休養後復職時猶需每日身穿護腰鐵衣工作，精神上必然受有極大之痛苦，因此請求精神慰撫金60萬元。
```

問題:
- 「支付**維修費用**」而非標準的「車輛維修費」
- 「**勞動能力減損之損害**20萬元」用了中文數字
- 「**精神慰撫金**60萬元」用了中文數字且段落很長

### 原因3: Prompt不夠明確
原有的完整性檢查清單:
```
□ 是否原始描述中的每個編號項目都已包含？
□ 是否包含了「減少勞動能力損失」（如果原始描述中有此項）？
□ 是否包含了「慰撫金」？
□ 項目數量是否與原始描述一致？
```

問題:
- 沒有明確要求「逐段落檢查」
- 沒有區分「不能工作損失」vs「勞動能力減損」
- 沒有明確「車輛維修費」的重要性

## 解決方案

### 修改位置
- **文件**: `KG_700_CoT_Hybrid.py`
- **函數**: `_generate_llm_based_compensation()`
  - 單原告prompt: line 1909-1935
  - 多原告prompt: line 2061-2087

### 新增的「逐段提取原則」

```markdown
⚠️ **逐段提取原則**（⭐ 非常重要）：
原始描述中的每一段文字如果包含金額，就必須對應一個獨立的損害項目！
- ✅ 如果看到「維修費用13,750元」→ 必須生成「車輛維修費用：13,750元」
- ✅ 如果看到「勞動能力減損之損害20萬元」→ 必須生成「勞動能力減損：200,000元」
- ✅ 如果看到「精神慰撫金60萬元」→ 必須生成「慰撫金：600,000元」
- ✅ 如果看到「不能工作損失156,000元」→ 必須生成「不能工作損失：156,000元」
- ⚠️ 注意：「不能工作損失」和「勞動能力減損」是**兩個不同的項目**，不要合併！
- ⚠️ 注意：「車輛維修費」和「車輛貶值」是**兩個不同的項目**，不要合併！
```

### 強化的完整性檢查清單

```markdown
⚠️ **完整性檢查清單**（輸出前必須確認）：
□ 是否原始描述中的每個段落（包含金額）都已轉換為一個損害項目？
□ 是否包含了「減少勞動能力損失」或「不能工作損失」（如果原始描述中有此項）？
□ 是否包含了「勞動能力減損」（如果原始描述中有此項，且它與「不能工作損失」是分開的）？
□ 是否包含了「車輛維修費用」（如果原始描述中有此項）？
□ 是否包含了「慰撫金」或「精神慰撫金」？
□ 輸出的項目數量是否 ≥ 原始描述中包含金額的段落數量？
```

## 關鍵改進

### 1. 明確「逐段對應」原則
- 從原來的「提取所有項目」改為「每個包含金額的段落 → 一個損害項目」
- 更具體、更可操作

### 2. 用具體例子說明
- 直接使用本案例中的實際措辭
- 「維修費用」→「車輛維修費用」
- 「勞動能力減損之損害20萬元」→「勞動能力減損：200,000元」

### 3. 明確區分相似概念
- **新增**: 「不能工作損失」≠「勞動能力減損」
- **新增**: 「車輛維修費」≠「車輛貶值」

### 4. 量化檢查標準
- 從「是否一致」改為「是否 ≥ 包含金額的段落數量」
- 給LLM一個明確的數值目標

## 預期效果

修改後,LLM應該能:
1. ✅ 識別「維修費用13,750元」並生成「車輛維修費用：13,750元」
2. ✅ 區分「不能工作損失156,000元」和「勞動能力減損200,000元」為兩個獨立項目
3. ✅ 在長段落中識別「精神慰撫金60萬元」並生成「慰撫金：600,000元」
4. ✅ 輸出項目數量 = 10項(律師輸入中包含金額的段落數)

## 後續修正 - 防止生成「未提供資訊」項目

### 問題
第一次修正後,用戶測試發現LLM開始生成大量「未提供資訊」的空項目:
```
（五）醫療輔具費用：未提供資訊
（六）精神損害慰撫金：未提供資訊
（七）減少勞動能力損失：未提供資訊
...
（十一）財物損失：未提供資訊
```

### 原因
1. Prompt中有「⚠️ **慰撫金必須列出**：無論原始描述如何，慰撫金必須作為獨立項目」
   - LLM誤以為需要列出所有「標準項目」
2. 沒有明確禁止生成原始描述中沒有的項目

### 解決方案
**修改位置**: `KG_700_CoT_Hybrid.py`
- 單原告prompt: line 1992-2000, 1929-1936
- 多原告prompt: line 2150-2158, 2087-2094

#### 1. 修改慰撫金規則 (line 1983, 2141)
```markdown
- ⚠️ **慰撫金必須列出**：如果原始描述中有提到慰撫金（或精神慰撫金），必須作為獨立項目列出
```
（移除「無論原始描述如何」）

#### 2. 新增禁止事項 (line 1992-2000, 2150-2158)
```markdown
【嚴格禁止事項】
- ❌ **絕對不可生成原始描述中沒有的項目**：
  * 如果原始描述中沒有提到某個損害項目，就不要生成該項目
  * 不要生成「未提供資訊」、「本案未提供」等標註
  * 不要使用固定模板列出所有可能的項目類型
  * 只生成原始描述中**實際存在且有金額**的損害項目
```

#### 3. 強化完整性檢查 (line 1929-1936, 2087-2094)
```markdown
⚠️ **完整性檢查清單**（輸出前必須確認）：
□ 輸出的項目數量是否 = 原始描述中包含金額的段落數量？（不多不少）
□ 是否有任何項目標註為「未提供」？（如果有，請刪除該項目）
```
