# 修復結論段落生成的錯誤原告姓名問題

## 問題描述

**用戶報告**："這篇很不錯,但是最後綜上所陳卻錯誤出現'原告林肜宇'字樣,是不是LLM不小心使用了錯誤的模板?"

**問題現象**：
- 單一原告案件的結論段落使用了「就原告林肜宇部分」的格式
- "林肜宇"這個姓名在輸入的律師資料中完全不存在
- 這是LLM從prompt中的範例複製了錯誤的姓名

## 根本原因分析

### 原因1：錯誤的多原告偵測邏輯 (KG_700_CoT_Hybrid.py:1158)

**原始程式碼**：
```python
# 檢查是否為多原告案件
is_multi_plaintiff = damage_section and '原告' in damage_section and damage_section.count('原告') > 2
```

**問題**：
- 使用啟發式方法（計算'原告'出現次數）來判斷是否為多原告
- 不準確，可能誤判單一原告為多原告
- 已經有準確的 `parties.get('原告數量', 1)` 資料卻沒使用

**修復後**：
```python
# 檢查是否為多原告案件（使用parties中的原告數量，更準確）
plaintiff_count = parties.get('原告數量', 1)
is_multi_plaintiff = plaintiff_count > 1
```

### 原因2：Prompt中的硬編碼範例姓名 (KG_700_CoT_Hybrid.py:1198)

**原始程式碼**：
```python
📝 **多原告特別要求**：
- ✅ 必須按原告分組：「就原告林肜宇部分，包含...；就原告吳彩雲部分，包含...」
```

**問題**：
- Prompt範例中直接使用了「林肜宇」、「吳彩雲」這樣的硬編碼姓名
- LLM學習這個範例時，直接複製了這些姓名到輸出中
- 即使是單一原告案件，LLM也可能錯誤地使用這些名字

**修復後**：
```python
📝 **多原告特別要求**：
- ✅ 必須按原告分組：「就原告XXX部分，包含...；就原告YYY部分，包含...」
- ⚠️ **重要**：使用「已整理的損害項目段落」中實際出現的原告姓名，不要使用範例中的姓名
```

### 原因3：單一原告prompt缺乏明確禁止 (KG_700_CoT_Hybrid.py:1210-1214)

**原始程式碼**：
```python
📝 **內容要求**：
- ✅ 只需列出「項目名稱」和「金額」，如：醫療費用54,741元、看護費用74,000元
- ✅ 單一原告不需要分組，直接列出所有損害項目即可
```

**問題**：
- 沒有明確禁止使用「就原告XXX部分」的格式
- LLM可能混淆單一原告和多原告的格式要求

**修復後**：
```python
📝 **單一原告案件特別要求**：
- ⚠️ **禁止使用**「就原告XXX部分」的格式（這是多原告案件才用的格式！）
- ✅ 正確格式：「被告應{liability_term}原告之損害，包含醫療費用XXX元、看護費用XXX元...」
- ✅ 只需列出「項目名稱」和「金額」，如：醫療費用54,741元、看護費用74,000元
- ✅ 單一原告不需要分組，不需要提及原告姓名，直接列出所有損害項目即可
```

## 技術原理

### 為什麼LLM會複製範例姓名？

LLM在生成文本時會學習prompt中的模式，包括：
1. **格式模式**：如「就原告XXX部分」
2. **範例內容**：如具體的姓名「林肜宇」

當範例中使用了具體的姓名時，LLM可能會：
- 直接複製這些姓名（即使它們不在實際輸入中）
- 誤以為這些是應該使用的標準姓名
- 將範例當作模板而非格式指南

### 解決方案的設計原則

1. **使用佔位符而非具體內容**：
   - ❌ 「就原告林肜宇部分」（具體姓名）
   - ✅ 「就原告XXX部分」（佔位符）

2. **明確指示來源**：
   - 添加：「使用『已整理的損害項目段落』中實際出現的原告姓名」
   - 這告訴LLM應該從哪裡獲取姓名

3. **明確禁止錯誤格式**：
   - 對於單一原告案件，明確禁止使用多原告格式
   - 使用「⚠️ **禁止使用**」強調重要性

4. **使用準確的判斷邏輯**：
   - 用 `parties.get('原告數量', 1)` 而非啟發式判斷
   - 確保案件類型判斷的準確性
