1. 第 6 頁 Introduction 架構圖

目前問題：

2. 第 14 頁 System Model

目前問題：
- 圖中仍使用 \Delta_{i,j}^{p} 或 Delta/delta 方向標記作為正式條件。
- 例如類似 d_{i,j}^{p} \leq \tau^u, \Delta_{i,j}^{p}>0 這種形式。

為何要改：
- 最新版本禁止把 \Delta_{i,j}^{p} 作為正式公式符號。
- 方向應由兩節點加權嚴重度高低判斷，而不是重新定義 Delta 符號。

建議改法：
- 移除 \Delta_{i,j}^{p}。
- 改成文字：
  LH keeps edges from lower weighted severity to higher weighted severity.
  HL keeps edges from higher weighted severity to lower weighted severity.
- 若一定要在圖中保留視覺差異，可在圖說說：
  signed delta is only a visual hint and is not an additional formal distance formula.

3. 第 20 頁 Problem Formulation

為何要改：
- A_{LH}(n_i)、A_{HL}(n_i) 已從最新主論文符號表移除。
- 最新第五章改用 query-specific retrieval trees 與
  \mathcal{V}_{LH}(\mathbf{q})、\mathcal{V}_{HL}(\mathbf{q})、
  \mathcal{V}_{\mathrm{SDKG}}(\mathbf{q})。

建議改法：
- 將 d_{i,j}^{p,\ell} 改為 d_{q,i}^{p,\ell}。
- 移除 A_{LH}(n_i)、A_{HL}(n_i)。
- 改寫為：
  The query is mapped to the closest observed case satisfying a(c_i,\mathbf{q}).
  The corresponding node n_i is used to initialize
  \mathcal{T}_{LH}^{p,u,\ell}(\mathbf{q}) and
  \mathcal{T}_{HL}^{p,u,\ell}(\mathbf{q}).

5. 第 57 頁 Phase 2: relation construction

目前問題：
- dominant feature group 條件看起來三行都寫成 b_{i,F}\cdot b_{j,F}>0。
- 第二、第三行若分別代表 injury 與 compensation，不能都用 F。
- 此頁也把主導特徵群寫得像正式公式，可能會讓老師追問。

為何要改：
- 最新版本不新增 G(p) 這類符號，而是用文字說明：
  主導特徵群由 \alpha^p、\beta^p、(1-\alpha^p-\beta^p) 中最大者決定。
- 若要寫公式，也要確保 Fact/Injury/Compensation 對應正確。

建議改法：
- 簡化為文字：
  A relation is constructed only when d_{i,j}^{p,\ell}\leq\tau^u and the two cases
  share at least one boolean feature in the dominant feature group.
- 主導特徵群用文字說明，不必用三行複雜公式。

6. 第 58 頁 Phase 2: E^{p,u,\ell}

目前問題：
- E^{p,u,\ell} 的公式只寫距離門檻 d_{i,j}^{p,\ell}\leq\tau^u。
- 缺少「共享主導特徵群中的至少一個 boolean feature」條件。

為何要改：
- 最新 E^{p,u,\ell} 同時需要：
  (1) d_{i,j}^{p,\ell}\leq\tau^u
  (2) 主導特徵群中至少共享一個 boolean feature。

建議改法：
- 在公式或文字中補：
  and share at least one boolean feature in the dominant feature group.
- 若不想讓公式太長，可保留距離公式，並在下一行文字補條件。

7. 第 60 頁 Query-time Anchor Mapping

目前問題：
- anchor formula 的 arg min 下標與距離下標不一致。
- 畫面上是類似 a(c_i,q) \Leftrightarrow c_i = arg min_{c_i\in D} d_{q,j}^{p,\ell}。
- 下標應該用 c_j\in\mathcal{D} 搜尋，再選出 c_i。
- q、D、c_i 也未與主論文粗體/花體一致。

建議改法：
- 改成：
  a(c_i,\mathbf{q}) \Longleftrightarrow
  c_i=\arg\min_{c_j\in\mathcal{D}}\{d_{q,j}^{p,\ell}\}.
- 文字補：
  The query is not inserted into the graph; it is mapped to an existing anchor case.

8. 第 62 頁 Parent selection

目前問題：
- 父節點選擇仍使用 A(n_j)。
- 公式距離看起來使用 d_{q,j}^{p,\ell}，但最新版父節點選擇用
  d_{h,j}^{p,\ell}。

為何要改：
- 最新第五章不使用 A(n_j) 作正式符號。
- h_j 是為 n_j 選一個已到達父節點，應比較 parent candidate 與 child node
  之間的距離。

建議改法：
- 改成：
  Let h_j denote the retained parent node of n_j.
  If multiple reached nodes can connect to n_j, select h_j by the smallest
  d_{h,j}^{p,\ell}.
- 不要使用 A(n_j)。

9. 第 63 頁 Candidate/retrieval sets

目前問題：
- 使用 C_{LH}(q)、C_{HL}(q) 作候選集合。
- 使用 R_{LH}(q)、R_{HL}(q) 分別 arg min。
- 使用 |R|=k_{LH}、|R|=k_{HL}。

為何要改：
- 最新版本已不用 C_{LH}/C_{HL}；改用
  \mathcal{V}_{LH}(\mathbf{q})、\mathcal{V}_{HL}(\mathbf{q})、
  \mathcal{V}_{\mathrm{SDKG}}(\mathbf{q})。
- 不再先分別選 R_{LH}^{k/2}、R_{HL}^{k/2}。
- 正式做法是先合併候選節點，再於 top-k budget 內依 d_{q,j}^{p,\ell} 選取
  \mathcal{R}(\mathbf{q})。

建議改法：
- 改成三步：
  1. Form \mathcal{V}_{LH}(\mathbf{q}) and \mathcal{V}_{HL}(\mathbf{q}).
  2. Let \mathcal{V}_{\mathrm{SDKG}}(\mathbf{q})
     = \mathcal{V}_{LH}(\mathbf{q})\cup\mathcal{V}_{HL}(\mathbf{q}).
  3. Select \mathcal{R}(\mathbf{q}) within top-k budget by d_{q,j}^{p,\ell}.

10. 第 64 頁 Directional retrieval budgets

目前問題：
- 使用 k_{LH}、k_{HL}。
- 使用 \lfloor k/2\rfloor。
- 寫成方向性 retrieval budget。

為何要改：
- 最新版本明確不強迫兩邊各 k/2。
- 也不使用 k_{LH}、k_{HL} 作正式輸出。

建議改法：
- 整頁建議重寫。
- 可改成：
  The final reference set \mathcal{R}(\mathbf{q}) is selected from
  \mathcal{V}_{\mathrm{SDKG}}(\mathbf{q}) under the top-k budget.
  If one direction has no comparable candidates, the system selects from the
  available direction only.
- 若要補公式，可用主論文最新版：
  \mathcal{R}(\mathbf{q}) =
  arg min_R \sum_{n_j\in R} d_{q,j}^{p,\ell},
  where n_j\in\mathcal{V}_{\mathrm{SDKG}}(\mathbf{q}) and
  |R|=\min\{k,|\mathcal{V}_{\mathrm{SDKG}}(\mathbf{q})|\}.
